# CLI и формат правок

Команды запускаются через `python -X utf8 graph_agent.py`. Глобальные опции ставятся **перед** командой:

- `--root PATH` — папка инструмента с `graph_content.py` и `data/`.
- `--data PATH` — другой собранный `graph.json`; для записи используйте `--root`, а не произвольный путь данных.
- `--max-chars N` — предел JSON-ответа, от 512, по умолчанию 6000 символов.

Чтение навигации, health и bootstrap не исполняет конфигурацию и не читает содержимое исходников, кроме ограниченного поиска маркеров при bootstrap. Команды записи загружают доверенный локальный `graph_content.py`, проверяют эффективное описание и сохраняют JSON-снимок. Не запускайте операции записи для чужой непроверенной Python-конфигурации.

## Чтение

| Команда | Результат |
| --- | --- |
| `overview` | Корень и разделы первого уровня |
| `search "запрос"` | Поиск по ID, названию, описанию и путям; все слова должны совпасть |
| `human-changes ID` | Постраничное сравнение человеческих правок «было → стало» |
| `node ID` | Описание, пути, тесты, дети, флаги, человеческие правки и связанные изображения |
| `context ID` | Узел и соседние зависимости |
| `path "relative/file.gd"` | Узлы, покрывающие путь; сначала наиболее точные |
| `health` | Пропавшие paths/tests, битые ссылки, циклы и отметки проверки |
| `bootstrap --scope src` | Предложения по маркерам `@orbit: node_id` |
| `history [ID]` | История правок целиком или для одного узла, от новых к старым |

`overview`, `search`, `path`, `health`, `bootstrap`, `history`, `human-changes` поддерживают `--limit` и `--offset`. В ответе есть `total`, `next_offset` и `truncated`. `context` поддерживает `--depth 0..3`, `--direction in|out|both`, `--hierarchy` и `--limit` (по умолчанию 8 узлов). Иерархия не включается в обход по умолчанию.

`health --scope src` ищет непривязанные подходящие файлы в указанной папке. `bootstrap --scope src --parent pillar_combat` также предлагает новые узлы по неизвестным маркерам и группам непривязанных файлов. Эти две команды принимают `--max-files` (по умолчанию 2000). Папки сборки, кеши, `node_modules`, `.git`, `.godot` и арты пропускаются; сканирование не следует по вложенным символьным ссылкам. Маркеры читаются в первых 128 КиБ файла.

`health` опирается на последний собранный граф. `rebuild_required` означает расхождение с конфигурацией: сначала пересоберите. Bootstrap отказывается создавать предложения по устаревшему графу. `scan_incomplete` сообщает о достижении лимита сканирования. Это проверка объявленных путей, не доказательство полноты архитектуры.

## Простые правки

```sh
python -X utf8 graph_agent.py update-node sys_damage_model --human "Расчёт урона и обработка попаданий" --paths src/combat/damage.gd --rebuild
python -X utf8 graph_agent.py set-status sys_damage_model live --rebuild
python -X utf8 graph_agent.py add-node sys_effects --parent pillar_visuals --tier 2 --label "Эффекты" --paths src/effects --rebuild
python -X utf8 graph_agent.py add-link sys_ai_commander sys_damage_model --type calls --label "Запрос атаки" --rebuild
python -X utf8 graph_agent.py remove-link sys_ai_commander sys_damage_model --rebuild
python -X utf8 graph_agent.py remove-node sys_effects --rebuild
```

`update-node` и `add-node` принимают `--label`, `--human`, `--status`, `--note`, `--tier`, `--parent`, `--paths`, `--tests`, `--needs-review true|false`, `--locked true|false`. `--paths`/`--tests` **заменяют** список; несколько путей задаются через пробел, путь с пробелами — в кавычках. Флаг без значений очищает список. Неуказанные поля сохраняются. Новому узлу по умолчанию назначается `idea`.

Для всех команд записи доступны:

- `--dry-run` — валидация и дифф без записи и сборки.
- `--expected-revision HASH` — отклонить правку, если исходная конфигурация уже изменилась.
- `--summary "..."` — краткое описание для журнала.
- `--rebuild` — после сохранения обновить данные карты и индексы. Без флага запросы к собранному графу остаются устаревшими.

Успех возвращает `saved`, `revision`, `rebuilt` и `diff`. Дифф перечисляет узлы, затронутые поля, добавленные/удалённые связи и настройки. Если дифф не помещается, остаётся `diff_summary` и `truncated: true`; признак успешной записи не теряется. Ошибка — JSON с `error` и ненулевой код завершения. Правка без изменений и без пересборки возвращает `unchanged: true` без нового снимка и события.

## Пакет изменений

Файл `patch.json` может содержать список операций или объект с полем `operations`:

```json
{
  "operations": [
    {"op": "add-node", "id": "sys_effects", "node": {"label": "Эффекты", "human": "Игровые визуальные эффекты", "parent": "pillar_visuals", "tier": 2, "status": "proto", "paths": ["src/effects"], "tests": []}},
    {"op": "add-link", "source": "sys_effects", "target": "sys_damage_model", "type": "reads_state", "label": "Результаты попаданий"},
    {"op": "update-node", "id": "sys_damage_model", "fields": {"needs_review": true}}
  ]
}
```

```sh
python -X utf8 graph_agent.py apply --file patch.json --dry-run
python -X utf8 graph_agent.py apply --file patch.json --expected-revision HASH_FROM_PREVIEW --summary "Связать эффекты с попаданиями" --rebuild
```

В одной транзакции допускается от 1 до 100 операций. Проверяется итоговый граф, поэтому связанные правки родителей и уровней можно делать вместе. Узел с детьми и корень удалить нельзя. Удаление конечного узла убирает его явные связи. Одна направленная пара узлов поддерживает одну явную связь; для её изменения удалите старую и добавьте новую в том же пакете. Автоматические родительские связи меняются через `parent`.

Схемы операций:

| op | Поля |
| --- | --- |
| `add-node` | `id`, `node` с `parent` и `tier` |
| `update-node` | `id`, `fields` |
| `set-status` | `id`, `status` |
| `remove-node` | `id` |
| `add-link` | `source`, `target`, необязательные `type`, `label`, `proposed` |
| `remove-link` | `source`, `target` |
| `acknowledge-node` | `id`, `token` из актуального `human_edit`, обязательный `note`: что прочитано и как это будет учтено |

Для `node`/`fields` допустимы: `label`, `human`, `status`, `tier`, `parent`, `paths`, `tests`, `note`, `hero`, `arts`, `sats`, `flag`, `proposed`, `autoexpand`, `color`, `family`, `codex_state`, `locked`, `needs_review`. Метки `human_edit` создаются сервером; обычной командой их подменить нельзя.

## Ознакомление с человеческими правками

```sh
python -X utf8 graph_agent.py node sys_damage_model
python -X utf8 graph_agent.py acknowledge-node sys_damage_model --token TOKEN_FROM_NODE --note "Уточнение назначения прочитано; сохраняю формулировку и учту её в задаче" --rebuild
```

Сначала агент читает `human-changes ID`, сообщает пользователю, какие изменения увидел и как их учтёт, затем записывает ознакомление с обязательным пояснением `--note`. Проверка требует непустой заметки, но сама программа не может доказать, что агент действительно всё понял или отправил сообщение; это также закреплено в `SKILL.md`.

Пока текущая человеческая правка не подтверждена, агент не может менять узел, его зависимости или состав дочерних узлов. Подтверждение можно включить отдельной операцией в пакет с узкой правкой, если агент действительно изучил текущую версию. Новое сохранение человеком меняет токен. `locked` продолжает запрещать содержательные правки; ознакомление не снимает блокировку.

В `human_edit` есть время, поля, токен и пояснение ознакомившегося агента. Команда `human-changes` выдаёт значения до и после правок; ещё не прочитанные изменения накапливаются между сохранениями. Программа не оценивает понимание агентом правки. За сохранение смысла отвечает агент и его инструкция. Прямые записи файлов обходят эту защиту. Сам журнал хранит роль `human`/`agent`, а не подтверждённую личность пользователя.

## Импорт как предложение

```sh
python -X utf8 graph_agent.py bootstrap --scope src --parent pillar_combat > proposed.json
```

Проверьте `truncated`, `scan_incomplete`, `next_offset`, `unresolved` и сами операции. Не применяйте вывод целиком, если он неполный: `apply` отвергает такой ответ. Для намеренного частичного импорта выпишите проверенные операции в отдельный файл. Новые узлы требуют осмысленных названий и описаний; ни папка, ни маркер не доказывают наличие зависимости.

## Сохранение

Браузер и CLI используют `graph_store.save_document`: межпроцессную блокировку, проверку версии, валидацию, резервную копию, журнал и откат при ошибке сборки. Отдельные файлы заменяются атомарно. Несколько файлов не образуют транзакцию, устойчивую к выключению питания; для долговременной истории используйте Git. Если процесс аварийно завершился, оставшийся `graph_write.lock` удаляется после проверки, что другой писатель не работает.
